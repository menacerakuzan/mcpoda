# @proyav/nazk

MCP-сервер до **Єдиного державного реєстру декларацій** НАЗК. Без ключів і реєстрації.
Сервер лише читає і нічого не додає до того, що реєстр уже опублікував.

Частина проєкту [ПРОЯВ](../../README.md) — Департамент цифрового розвитку, інформаційної
політики та кіберзахисту Одеської обласної державної адміністрації.

Перед читанням коду варто прочитати [правову записку](LEGAL.md): вона пояснює, чому цей
сервер влаштований інакше за сервер закупівель.

## Підключення

```json
{
  "mcpServers": {
    "proyav-nazk": {
      "command": "npx",
      "args": ["-y", "@proyav/nazk"]
    }
  }
}
```

## Tools

| Tool | Що робить |
|---|---|
| `proyav_search_declarations` | Пошук за прізвищем, роком, типом декларації |
| `proyav_get_declaration` | Одна декларація: доходи, майно, транспорт, корпоративні права |
| `proyav_declarant_history` | Усі декларації однієї особи по роках, з позначкою чинної |
| `proyav_compare_declarations` | Що змінилось між двома деклараціями однієї особи |

## Чим цей сервер відрізняється від сервера закупівель

**Локального індексу немає і не буде.** Закупівлі індексуються повністю, бо без цього
частина даних недосяжна. Декларації — ні: мільйони записів про людей на чужому ноутбуці
це вже не доступ до відкритих даних, а копія реєстру персональних даних поза контролем
держателя. Запити йдуть до джерела на вимогу.

**Вижимка мінімізує навіть те, що опубліковано.** Реєстр сам вимарює паспорт, податковий
номер, УНЗР і точну адресу. Сервер додатково не передає адрес узагалі та дат народження
родичів: вони відкриті, але переказувати дату народження дитини в розмову з асистентом
немає підстав. Лишаються самі звʼязки: дружина, син, мати.

**Формулювання жорсткіші.** «Незадеклароване», «приховане», «необґрунтовані активи» це
юридичні кваліфікації, які має право робити НАЗК і суд. Сервер їх не вживає, і це
перевіряється тестом.

## Пастка, заради якої написано половину коду

Одна людина часто подає **дві декларації за один рік**: щорічну і пізнішу уточнену.
Обидві мають однаковий код типу, тому відрізнити їх за типом неможливо.

Реальний випадок із реєстру: у декларанта за 2024 рік дві декларації, і в одній 175
обʼєктів нерухомості, а в іншій 22. Порівняння не тієї пари дає «людина втратила 150
обʼєктів нерухомості» — найшкідливіше речення, яке цей сервер міг би вимовити.

Тому:

- `proyav_declarant_history` позначає кожну декларацію полем `current`: чинна вона чи
  замінена пізнішою;
- `proyav_compare_declarations` сам підтягує історію декларанта і попереджає, якщо
  взято замінену декларацію або дві декларації одного року.

Обидва попередження перевірені на живих даних і покриті тестами.

## Джерело

`public-api.nazk.gov.ua/v2`. Перевірено 25.08.2026.

- `GET /documents/list` — пошук: `query`, `declaration_year`, `declaration_type`,
  `user_declarant_id`, `page`. Стеля видачі 10 000 документів, про що сервіс каже полем `notice`
- `GET /documents/{id}` — повна декларація за розділами `step_0` … `step_17`
- Ключів і реєстрації не потрібно

## Доступність джерела

Реєстр відповідає з українських адрес і віддає **403 Forbidden** запитам із зарубіжних,
зокрема з раннерів GitHub Actions. Це виявилось не з документації, а з червоного CI.

Тому контрактні тести спершу перевіряють доступність і, якщо реєстр не відповідає,
пропускають набір із поясненням замість того, щоб валити збірку. Червоний CI з причини
«реєстр не пускає раннер» привчає ігнорувати червоне, а тихий успіх сховав би справжню аварію.
