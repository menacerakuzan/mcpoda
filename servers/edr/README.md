# @proyav/edr

MCP-сервер до Єдиного державного реєстру юридичних осіб, ФОП та громадських формувань
(ЄДР): засновники, керівники/підписанти, кінцеві бенефіціарні власники — і головне,
чи є спільна людина серед них у двох різних компаній.

Це доповнення до `@proyav/prozorro`: `proyav_check_tender` там уже шукає збіги телефону,
адреси й контактної особи серед учасників тендеру. Цей сервер додає той самий тип сигналу,
але через офіційний реєстр, а не через дані самого тендеру.

## Чому це окремий сервер, а не живий API

19.01.2026 Мін'юст відновив публікацію відкритих даних ЄДР після воєнного відключення.
Перевірено 26.08.2026: доступ вільний, без ключів і реєстрації, CC BY 4.0. Але це не API —
це **щотижневий повний XML-дамп** усього реєстру (`data.gov.ua`, датасет ЄДР), окремо для
юросіб (UO), ФОП (FOP) і відокремлених підрозділів (FSU). Немає ні пошуку по одній компанії,
ні інкрементального фіда — тільки файл на ~3.2 ГБ розпакованого XML для самих юросіб.

Тому замість крауля, як у Prozorro, тут одноразовий (і щотижневий за бажанням) імпорт
локального файлу в SQLite-індекс. Сервер сам нічого не качає з мережі.

## Джерело даних

- Сторінка датасету: `data.gov.ua`, «Єдиний державний реєстр юридичних осіб, фізичних
  осіб-підприємців та громадських формувань»
- Використовується лише `UO.zip` (юридичні особи). ФОП (`FOP.zip`) не імпортуються:
  учасники тендерів Prozorro, зареєстровані як ФОП, не мають засновників/бенефіціарів
  у розумінні цього реєстру, тому файл не додає сигналу, який шукає цей сервер.
- Формат: `windows-1251`, один `<SUBJECT>` на юридичну особу. Схема (`UO_schema.xsd`)
  зберігає засновників/підписантів/бенефіціарів як вільний текст в одному полі
  («Прізвище Ім'я По батькові; ЄДРПОУ, якщо юрособа; частка»), а не як окремі поля —
  сервер розбирає цей текст евристично, це не парсинг структурованих даних.

## Встановлення індексу

```bash
curl -L -o UO.zip "https://data.gov.ua/dataset/03cc1239-3988-4451-aa0d-aadb77448714/resource/d40cc921-39bb-44fd-be06-dc02589f45c6/download/uo.zip"
unzip UO.zip
npm run import -- --file=./UO.xml
```

Імпорт повністю перезаписує кожну компанію, яку зустрічає (`insert ... on conflict do update`
+ видалення й вставка людей наново) — це узгоджено з тим, що джерело саме повний знімок,
а не дельта. Повторний прогін тим самим файлом ідемпотентний.

Пряме посилання на `uo.zip` може змінюватись — якщо `curl` поверне 404, візьміть актуальне
посилання зі сторінки датасету на `data.gov.ua` вручну.

Обидва посилання і перелік полів, які читає парсер, лежать у [`src/source.ts`](src/source.ts),
а `npm run test:contract` щоразу перевіряє їх проти живого джерела: чи віддає дамп файл
потрібного порядку і чи оголошує схема всі поля, на які спирається розбір. Це три кілобайти
трафіку і пів секунди, і саме воно ловить той тип поломки, який інакше виглядає як
«імпорт чомусь дав нуль компаній».

`npm run index:stats` показує кількість компаній, людей і час останнього імпорту.

## Обмеження, які треба тримати в голові

**Збіг за іменем — не збіг за особою.** Масовий дамп не несе стабільного ідентифікатора
фізособи. Два «Іван Петренко» без жодного стосунку одне до одного дадуть однаковий збіг
у `proyav_edr_shared_people`. Інструмент повертає це застереження в кожній відповіді зі
збігами — воно має переказуватись людині так само, як і сигнали в `proyav_check_tender`.

**Парсинг вільного тексту — евристика, не гарантія.** Поля на кшталт SIGNER іноді містять
повний текст довіреності в дужках перед роллю. Ім'я витягується як текст до першої «;»
або дужки, з відсіченням завершального «- роль». Складні чи нетипові формулювання можуть
дати неточне ім'я; парсер розрахований на типові випадки, підтверджені на реальному дампі
26.08.2026, а не на кожен можливий варіант формулювання за 30 років реєстрації.

**Тиждень відставання.** Індекс такий свіжий, як останній прогін `import`. Реєстр
оновлюється щотижня, тому в моменті дані можуть відставати на кілька днів.

Приватність людей, чиї імена потрапляють в індекс, розписана окремо в [LEGAL.md](LEGAL.md).

## Інструменти

- `proyav_edr_company` — картка компанії за ЄДРПОУ: назва, стан, усі пов'язані люди.
- `proyav_edr_shared_people` — спільні імена серед засновників/керівників/бенефіціарів
  двох компаній, разом із застереженням про однофамільців.
